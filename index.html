대표 사례

실제 운영 환경에서 문제를 찾고 개선까지 연결한 경험입니다.

01장애 분석Java / JEUS / WebToB / Network

문제 상황

이중화 환경에서 간헐적으로 반복된 엑셀 다운로드 실패

수개월 동안 오류가 이어졌지만 화면과 기존 로그만으로는 원인이 드러나지 않았습니다.

확인·추적

애플리케이션 로그와 통신 패킷을 확인하고, 세션 정보와 실제 요청값을 단계별로 대조했습니다.

해결

세션과 요청값이 일치하지 않는 구간을 특정해 분석 근거를 협력업체에 전달했습니다.

결과

처리 방식과 자원 사용 개선으로 연결하고 운영 환경에서 정상 동작을 확인했습니다.

02보안Java / JSP / MyBatis / MariaDB

문제 상황

JSP에서 조합한 SQL에 입력값이 직접 반영되던 구조

운영 중인 게시판의 기능과 권한 조건은 유지하면서 SQL Injection 취약 구간을 개선해야 했습니다.

분석

SQL 생성 지점과 게시판별 조회·인증·권한 조건, 파일 처리 흐름을 확인했습니다.

해결

DAO·MyBatis Mapper 구조를 구성하고 문자열 결합 SQL을 파라미터 바인딩 방식으로 전환했습니다.

결과

데이터 접근 역할을 분리했으며 이후 1년 이상 모의해킹 점검에 안정적으로 대응했습니다.

03업무시스템Nexacro / Java / Oracle / PL/SQL

업무 상황

서로 다른 업무 규칙을 운영 중인 차세대 시스템에 반영

오픈 이후에도 현업별 신규 기능과 개선 요청이 이어져 기존 기능에 미치는 영향을 함께 검토해야 했습니다.

분석

요구사항을 화면 상태, 서버 분기, 데이터 처리 조건으로 나누고 기능별 영향 범위를 확인했습니다.

개발

수수료·출력물 승인·검사일지·법조치 조회의 화면, Java 서비스, Oracle 프로시저를 개발했습니다.

운영

소스 반영부터 사용자 문의와 장애 대응까지 이어서 수행하며 오픈 이후 안정화를 지원했습니다.

04데이터 처리Oracle / SQL / Java Transaction

문제 상황

다채권 고객의 데이터 변경 시 일부 이력·마스터가 누락될 가능성

한 고객에게 여러 채권과 발송 이력·우편 이력·마스터가 연결되어 있어 변경 대상을 정확히 정해야 했습니다.

분석

공통 업무 키와 테이블 관계를 확인하고 다채권 고객의 전체 변경 대상과 예외 범위를 조회했습니다.

해결

연결된 이력·마스터 변경을 하나의 Java 트랜잭션 안에서 처리했습니다.

검증

변경 전후 조회 결과를 비교해 누락되거나 과도하게 반영된 데이터가 없는지 확인했습니다.
